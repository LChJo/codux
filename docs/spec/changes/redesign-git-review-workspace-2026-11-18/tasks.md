# 实施与验收

桌面实现已接入工作区、Git 侧栏和共享 Git 服务。自动化回归覆盖历史分页、首提交、合并提交父节点、重命名、暂存边界、远程工作树路由和 605 个文件的比较结果。窄栏视觉与鼠标、键盘的完整交互仍列在下方原生窗口验收项中。

## 1. 评审布局与 Git 侧栏

- [x] 将评审中的 Git 侧栏、变动文件和差异排成三栏，复用 Git 侧栏视图和评审分栏。评审中隐藏工作树与常用命令列并回收其宽度。
- [x] 将评审临时展开、评审内开关与非评审常驻偏好纳入可见性逻辑。
- [ ] 在原生窗口验证从侧栏关闭或已开启的状态分别进入评审，在评审中切换侧栏，再返回终端和文件。检查原布局、提交草稿、作用范围和滚动位置。
- [ ] 验证点击工具栏、快捷键与历史提交等入口进入评审时使用同一布局。窄窗中验证可收起侧栏和可切换统一 diff。

## 2. 文件宽度与悬停

- [x] 按文件行实际可用宽度分配文本宽度。目录先缩，根目录行回收目录宽度。
- [x] 复用悬停层展示全名、相对路径、状态、已有增删行数以及重命名前后路径。
- [x] 使用虚拟列表渲染评审行并支持路径筛选。Git 服务回归用 605 项验证可读取末尾文件。
- [ ] 在原生窗口以截图相当的宽度验证 `package.json`、`package-lock.json` 和 `CHANGELOG.md` 完整显示，检查长路径换行、所有行区域的悬停、滚动关闭提示、末尾文件和窄栏截断。

## 3. 历史与差异

- [x] 完成「更改 / 历史」导航、历史搜索和分页。提交详情显示明确的比较范围，文件可在相邻差异区打开。
- [x] 自动化验证未提交、分支比较和提交详情的范围，覆盖首提交、合并提交切换父提交、重命名、二进制以及工作区有修改时查看旧提交。
- [x] 实现刷新、失败和空状态的区分，按工作树、比较及请求版本应用异步结果。
- [x] 比较状态绑定项目与工作树的访问版本，清理切换后失效的状态；增加项目往返及关联工作树切换的回归测试，避免恢复无法完成的加载。
- [x] 返回评审时重新读取当前比较，刷新离开期间的暂存或提交变化；同一比较继续保留有效文件选择及滚动位置。
- [x] 历史提交行启用 GPUI 原生键盘焦点，支持 Tab 导航及 Enter、空格激活。
- [ ] 在原生窗口验收两次点击查看历史文件差异，快速切换文件、项目或工作树，以及晚到的结果与加载反馈。
- [ ] 在原生窗口验证离开评审后暂存或提交再返回的内容刷新，以及 Tab 聚焦历史行后按 Enter 打开提交。

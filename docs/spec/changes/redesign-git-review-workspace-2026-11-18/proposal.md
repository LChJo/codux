# 重设计桌面 Git 评审工作区

## 背景

现有评审把文件名限制在固定比例内。根目录文件没有目录文案，文件名仍可能显示为 `package...` 或 `READM...`，同名和相似文件也缺少整行悬停提示。进入评审时，现有视图切换会清空助手面板，工作树和常用命令仍占据一列。查看评审差异和使用 Git 侧栏需要来回切换。

## 变更

- 进入「评审」时自动展开 Git 侧栏。评审内容从左到右为 Git 侧栏、变动文件列表和文件差异。暂停显示工作树和常用命令所在列，把空间交给评审区域。
- Git 侧栏提供独立开关，并可在终端、文件等工作区常驻。退出评审时按用户设置恢复 Git 侧栏和原工作区布局。
- 文件行先给文件名分配宽度，目录先缩减，空目录不占宽。仅当实测空间不足时才截断文件名。整行悬停显示完整路径和已有的变更信息。
- 将工作区更改、分支比较和单次提交接入同一个评审工作区。保留明确的比较范围、紧凑的 Git 侧栏和可调整的分栏。

整体参考 VS Code 源代码管理的面板组织和导航方式，沿用 Codux 的视图、主题和组件。

## 范围

本提案涵盖桌面 GPUI 布局、Git 侧栏、文件列表、历史入口和差异交互。前次调查提出的 Git 依赖补丁、监听调度和引擎对照测量独立跟踪。
